# Testing Bricksmith

> **Status (2026-11-14):** the test **harness** exists (P1): hosted Swift Testing bundle, isolation, fixture
> library, scripts. The characterisation tests themselves are P2. Items still marked *(planned)* arrive in P2.

## Why tests come first
The Swift port rewrites the code class by class, and the tests are what show whether behaviour changed.
They are **characterisation tests**: they record what the Objective-C app does today, bugs included, and
they are written in Swift against the ObjC API. When a class is later ported to Swift, its tests run
unchanged against the new code.

## Running

```zsh
scripts/build.sh                   # clean build; fails on any warning not in docs/warnings-baseline.txt
scripts/build.sh --release         # same for Release (docs/warnings-baseline-release.txt)
scripts/test.sh                    # hosted unit/characterisation tests + coverage (build/coverage.txt);
                                   #   fails if the user's com.AllenSmith.Bricksmith defaults changed
scripts/test.sh --only BricksmithTests/HarnessFixtureLibraryTests   # a subset
scripts/test.sh --ui               # also the XCUITest smoke tests (scheme Bricksmith-UITests); real windows on screen
scripts/test.sh --ui-only --only BricksmithUITests/SmokeUITests   # UI tests alone, for iterating
scripts/dev/coverage-tiers.py      # P2 coverage gate: tier A/B per class, raw and effective (after docs/coverage-ledger.tsv)
scripts/dev/leaks-smoke.sh         # Debug app on fixture copies under `leaks --atExit` (P3 exit)
scripts/mutation-smoke.sh          # each scripts/mutations/*.patch must make a test fail
scripts/perf-compare.sh --run      # build+run perf tests in the Perf configuration, compare with docs/perf-baseline.json
scripts/perf-compare.sh            # compare existing build/perf-results.json (≤ +20%; a missing metric fails)
scripts/perf-compare.sh --update-baseline   # deliberate only; explain in the commit
scripts/make-ldraw-mini.py         # regenerate trunk/Fixtures/ldraw-mini from a full library (read-only source)
RECORD_GOLDENS=1 scripts/test.sh   # (planned, P2) regenerate goldens - deliberate only; review the diff
```

The tests run inside the app (`TEST_HOST`). In Xcode, use the `Bricksmith` scheme's Test action (⌘U).

## Writing a test (harness conventions)

- Put the file in `trunk/Bricksmith/Tests/Unit/`, and add it to the `BricksmithTests` target (with the `xcodeproj`
  gem, see LEARNINGS L11–L12). Start it with `import Testing` and `@testable import Bricksmith`. ObjC classes are
  visible through the app's bridging header.
- **Anything that touches the LDraw library or global state** must use `@Suite(.fixtureLibrary, .serialized)`.
  Each test then gets a temporary copy of `ldraw-mini` (`FixtureLibrary.current`), with singletons reset and output
  settings pinned. See `Tests/Support/FixtureLibrary.swift`.
- **Before the first test of a header,** annotate that header for nullability and generics in the same commit
  (plan v3.1 rule), and log any `null_unspecified` in port-status.md.
- **Crashing behaviour** goes in an exit test: `await #expect(processExitsWith: .failure) { … }`. It runs in a child
  process (L25). Use exit tests sparingly, because each costs about 1.5 s.
- **Known bugs** use `withKnownIssue("BUG-nnn: …") { … }` around an assertion of the *correct* behaviour.
- Fixture paths: `FixturePaths.trunk`, `.fixtures`, `.ldrawMini` and `.testData` are derived from `#filePath`.

## Coverage targets
- **Tier A ≥ 90%:** model and format classes.
- **Tier B ≥ 80%:** libraries and app logic.
- **Tier C:** every model-changing document action is automated or on the manual-only list.

Tiers are defined in plan §5 P2. Any code left uncovered in tiers A and B is listed, with a reason, in the
uncovered-line ledger in [port-status.md](port-status.md).

Tests that need the full LDraw library are tagged `.requiresFullLibrary`, and they skip themselves when it
isn't present.

## Rules
- **Goldens are a contract.** Regenerate them only on purpose, through a script flag (`RECORD_GOLDENS=1`).
  The commit that changes them must explain why. A port commit must never change goldens.
- **Known bugs** are recorded with `withKnownIssue`, not deleted or skipped. They are listed below.
- **Never touch real user preferences or libraries.**
  - Tests run hosted in the app. When `XCTestConfigurationFilePath` is set, the app launches in test mode:
    - **It keeps** the shared GL context and the Inspector, because documents need them.
    - **It skips** LDraw-path discovery, the catalog load, the part browser and LSynth menu setup,
      Sparkle, and every defaults write at quit.
  - The fixture library is injected with `+[LDrawPaths setOverrideLDrawPath:]`. Launch arguments aren't used,
    because the real defaults key is `"LDraw Path"`, which contains a space.
  - `Fixtures/ldraw-mini` is copied to a temp directory for each run, because the catalog builder writes
    `parts.plist` into it.
  - Debug builds (including the test host) use their own preferences domain, `com.AllenSmith.Bricksmith.debug`.
    `scripts/test.sh` **fails** if the installed app's real domain (`com.AllenSmith.Bricksmith`) changes during a run.
    It **restores** the debug domain to its pre-run snapshot, because AppKit autosave and Sparkle write there
    whenever nibs load (L33).
  - Test mode is detected from `XCTestConfigurationFilePath` (hosted tests), `SWT_EXIT_TEST_ID` (exit-test child
    processes) or `BRICKSMITH_TEST_MODE=1` (UI tests).
- **Singletons and statics:**
  - Suites that touch `ColorLibrary`, `PartLibrary`, `LDrawPaths`, `ModelManager`, `MLCadIni` or the
    `LDrawUtilities` statics call `+resetForTesting` and are marked `.serialized`.
  - The column setting and `defaultAuthor` are **pinned** per test. In the real app the author comes from
    `NSFullUserName()`; in tests it's fixed.
- **Goldens compare bytes** of `dataOfType:` (CRLF, UTF-8). `.gitattributes` stops git rewriting line endings.
  `Localizable.strings` is part of the output contract, so a port commit must not change it.
- **Accessibility identifiers** may be added to xibs for XCUITest. That doesn't count as a behaviour change.
- **Drawing** is characterised through `Tests/Support/RecordingRenderer.swift`. It implements the
  `LDrawRenderer`/`LDrawCollector` protocols and logs every call (`golden/drawing/*.txt`). The Metal renderer
  should reproduce the same stream. Suites that select primitives or draw textures need
  `OffscreenGL.makeCurrent()` (L70).
- **UI smoke tests** (`Tests/UI/SmokeUITests.swift`, row 17) are deliberately thin:
  - Every test opens a **temp copy** of a fixture, with `BRICKSMITH_TEST_MODE=1`, the fixture library, and
    `-"LDraw Path"` in the argument domain.
  - Byte checks reuse the approved round-trip goldens: after undo + save, or Save As, the file must equal
    `golden/roundtrip/<name>.ldr`.
  - Quirks of driving AppKit are listed in LEARNINGS L68. Don't type or click in the app's windows while they run.
- **Document tests** use `DocHarness.open` (`Tests/Unit/DocumentSpikeTests.swift`):
  - It loads the nib (`makeWindowControllers`, then touching `.window`) and orders the window in **fully transparent**
    with a fixed frame (L58).
  - It turns off event-based undo grouping; each operation is wrapped in `DocHarness.action`, which stands in for one
    user event.
  - Selection goes through `selectDirectives:`, i.e. the outline view.
- **Call ObjC that might throw through `ObjC.run { … }`.** An uncaught NSException on a test thread is swallowed by
  AppKit and the test hangs (L57). Document suites also carry `.timeLimit(.minutes(1))`.
- **Performance tests** (`PerformanceTests`) run only through `scripts/perf-compare.sh --run`.
  - They use the **Perf** build configuration: a Release clone with testability enabled, which defines
    `BRICKSMITH_PERF`. Debug timings are meaningless for comparing Swift with ObjC.
  - Each metric is the best of 15 runs after 2 warm-ups, on a 20,000-part synthetic model (L65).
  - The baseline belongs to the machine recorded in it; comparisons on other machines fail with a message.
  - **Noise band** (Mac15,7, five back-to-back runs on a quiet machine, commit `1ee0869`, 2026-11-16), as % of
    baseline:

    | Metric | Runs | Spread | Coefficient of variation |
    |---|---|---|---|
    | `archive_20000_parts` | 84-96% | 12 pt | 5.1% |
    | `copy_20000_parts` | 89-113% | 24 pt | 10.7% |
    | `draw_20000_parts_x20` | 82-93% | 11 pt | 5.1% |
    | `parse_20000_parts` | 92-100% | 8 pt | 3.3% |
    | `write_20000_parts` | 91-96% | 5 pt | 2.0% |

    How to read a result:
    - A single run moving by less than the spread above is noise. `copy` (12 ms) is the noisiest: one quiet run
      reached 113%, close to the 120% budget, so a single `copy` failure needs a rerun before it means anything.
    - To claim a real change (faster or slower), run at least three times and compare medians; a change smaller than
      about 10 points (25 for `copy`) isn't distinguishable from noise.
    - Other load on the machine (builds, other agents' test runs) widens the band. Measure on a quiet machine.
    - In this measurement every metric ran below its baseline. Don't read that as a speed-up from P4: the baseline
      was recorded on a working desktop (L65). Re-baselining is a deliberate decision (`--update-baseline`).
- **Randomised tests** use a fixed seed, and they print it when they fail.
- **Render snapshots** (`RenderSnapshotTests`) render fixtures in the real `LDrawGLView` from a fixed orthographic camera
  (zoom 400%, centred), capture with `-saveImageToPath:` after an explicit `-draw` (L64), and flip the image upright.
  - References live in `golden/render/<hw.model>/`. A machine without references skips the comparison rather than
    failing.
  - Tolerance: channel delta ≤ 8, with at most 0.5% of pixels exceeding it.
  - These images are the visual reference for the later Metal renderer.

## Known issues
Bugs live in **[KNOWN-BUGS.md](KNOWN-BUGS.md)**. Don't fix them during the port. For each bug:
1. Log it in KNOWN-BUGS.md.
2. Write a test that asserts the *correct* behaviour, wrapped in `withKnownIssue` (or `XCTExpectFailure`).
3. Reference the bug ID in the test, e.g. `withKnownIssue("BUG-001: …")`.

Fixes happen after the port, in P12.

## Manual smoke checklist
**🧑 HUMAN GATE.** Debug builds use their own preferences domain (`com.AllenSmith.Bricksmith.debug`), so this never touches the installed
Bricksmith's settings. Run this at every phase exit gate, using a Debug build and the **full LDraw library**, for the
things automation covers poorly. Record the sign-off in port-status.md.

1. Launch the app. There are no error dialogs, and the LDraw folder is found (or the folder prompt works).
2. Open a **temporary copy** of `trunk/Test Data/Good/spider gearbox v2 opens.ldr` (never the fixture itself, because saving rewrites it). The model renders.
3. Rotate, pan and zoom the 3D view with the mouse and trackpad. Switch through the viewport layouts.
4. Select a part in the 3D view, then in the outline. The inspector shows its values. Change its colour and position from the inspector.
5. Drag a part from the part browser into the model. Move it with the arrow keys, rotate it with the rotation panel, then undo and redo all of it.
6. Copy and paste a part, both within one document and between two documents.
7. Add a step and use step navigation. Add a submodel to an MPD, reference it, then rename it. Earlier parts may shift
   slightly when a step adds parts further from the origin: this is by design, not a bug. The camera distance is
   6.5 × (the farthest corner of the bounding box of the steps shown, + 40) (`-[LDrawGLCamera tickle]`), so the
   perspective changes.
8. Marquee-select several parts and delete them. Undo.
9. Save As a new file, close it, reopen it. Content is identical (`diff` the files).
10. Open Preferences and change the grid spacing. Restart the app; the setting is kept.
11. Use the Minifigure generator and add a minifig to the model.
12. Add an LSynth hose and regenerate it.
13. Close every document while it has unsaved changes. Each save prompt works, and nothing crashes.
14. Select a few parts **of different colours** and use Randomize Colors. Each part gets one of the colours already in the selection (with one colour selected nothing changes, by design); Undo restores them.
15. Export Steps to a temporary folder. One file per step is written (they come out in reverse order: BUG-011).
16. Open Find, search by part and by colour; matching parts are selected.
17. Hide a part, then Show All. Use Add Related Part from a part's context menu; the related part is added and Undo removes it.
18. Panels and menus open, close and reopen without crashing (P4 changed how their nib objects are kept alive):
    - Inspector with every kind of selection (part, line, triangle, quad, conditional line, comment, unknown
      command, step, MPD model, LSynth), fast selection changes, nothing selected, several selected, and editing a
      field then changing the selection.
    - Dimensions and Piece Count: open, OK, reopen several times, then keep working in the document.
    - Move panel twice; Minifigure generator open, OK, reopen; tool palette show and hide.
    - Preferences: every tab, the LDraw folder and LSynth executable/config choosers; close, reopen, repeat.
    - Context menus: add and remove a favourite in the parts table; use the 3D view's menu, close the document,
      open another, use the menu again.
