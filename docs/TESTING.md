# Testing Bricksmith

> **Status (2026-11-14):** there is no automated test suite yet. Phases P1 and P2 of
> [swift-port-plan.md](swift-port-plan.md) build it. The sections marked *(planned)* describe how it
> will be laid out, so that everyone builds to the same shape. Update this file as each piece lands.

## Why tests come first
The Swift port rewrites the code class by class, and the tests are what show whether behaviour changed.
They are **characterisation tests**: they record what the Objective-C app does today, bugs included, and
they are written in Swift against the ObjC API. When a class is later ported to Swift, its tests run
unchanged against the new code.

## Running *(planned)*

```zsh
scripts/build.sh               # build the app; prints the warning count and compares it with docs/warnings-baseline.txt
scripts/test.sh                # unit and characterisation tests, with a coverage summary
scripts/test.sh --ui           # also run the XCUITest smoke tests
scripts/fetch-ldraw.sh         # optional: download the full LDraw library to ~/Library/Caches (never committed)
```

Tests that need the full LDraw library are tagged `.requiresFullLibrary`, and they skip themselves when it
isn't present.

## Layout *(planned)*

| Path | Contents |
|---|---|
| `trunk/Bricksmith/Tests/Unit/` | Swift Testing suites, one file per area. Areas follow plan §5 P2 (`RoundTripTests`, `MatrixMathTests`, `ColorLibraryTests`, …). |
| `trunk/Bricksmith/Tests/Perf/` | XCTest `measure` baselines. |
| `trunk/Bricksmith/Tests/UI/` | XCUITest smoke tests. |
| `trunk/Fixtures/ldraw-mini/` | A minimal, hand-built LDraw library: `LDConfig.ldr`, a few parts and primitives, `parts.lst`. |
| `trunk/Fixtures/ldr/` | Input models for round-trip tests. Each file targets one feature, plus a few realistic models. |
| `trunk/Fixtures/golden/` | Expected `write` output and render images. They are generated by the ObjC build and reviewed by a person. |
| `trunk/Test Data/` | Original regression fixtures (`Good/` opens; `Bad/` crashes because of line type `11`). |

## Rules
- **Goldens are a contract.** Regenerate them only on purpose, through a script flag (`RECORD_GOLDENS=1`).
  The commit that changes them must explain why. A port commit must never change goldens.
- **Known bugs** are recorded with `withKnownIssue`, not deleted or skipped. They are listed below.
- **Never touch real user preferences.** Tests point `LDrawPaths` at `Fixtures/ldraw-mini` through a test
  defaults domain.
- **Randomised tests** use a fixed seed, and they print it when they fail.
- **Render snapshot comparisons** use a tolerance. The reference machine is recorded with the images.

## Manual smoke checklist
Run this at every phase exit gate, using a Debug build, for the things automation covers poorly.

1. Launch the app. There are no error dialogs, and the LDraw folder is found (or the folder prompt works).
2. Open `trunk/Test Data/Good/spider gearbox v2 opens.ldr`. The model renders.
3. Rotate, pan and zoom the 3D view with the mouse and trackpad. Switch through the viewport layouts.
4. Select a part in the 3D view, then in the outline. The inspector shows its values. Change its colour and position from the inspector.
5. Drag a part from the part browser into the model. Move it with the arrow keys, rotate it with the rotation panel, then undo and redo all of it.
6. Copy and paste a part, both within one document and between two documents.
7. Add a step and use step navigation. Add a submodel to an MPD, reference it, then rename it.
8. Marquee-select several parts and delete them. Undo.
9. Save As a new file, close it, reopen it. Content is identical (`diff` the files).
10. Open Preferences and change the grid spacing. Restart the app; the setting is kept.
11. Use the Minifigure generator and add a minifig to the model.
12. Add an LSynth hose and regenerate it.
13. *(If you have the hardware)* Move the view with a 3Dconnexion mouse.
14. Close every document while it has unsaved changes. Each save prompt works, and nothing crashes.
